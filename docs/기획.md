# Git Reward 기획서

> 2026 교내 해커톤 / 팀 YDAA
> 이 문서는 프로젝트의 계약서다. 여기 정의된 데이터 형태와 파일 구조는 임의로 바꾸지 않는다.

---

## 1. 한 줄 정의

깃허브 기여 기록을 RPG 캐릭터 카드로 바꿔 디스코드에 보여주는 서비스.

## 2. 왜 만드는가

팀 과제에서 누가 무엇을 얼마나 했는지 잘 드러나지 않는다. GitHub에 기록이 남아 있어도 통계 메뉴를 직접 찾아 들어가야 하고, 표와 그래프뿐이라 다시 열어볼 이유가 없다.

Git Reward는 그 기록을 캐릭터 능력치로 바꿔, 팀이 하루 종일 켜두는 디스코드로 먼저 보낸다. 기록을 **보여주는** 데서 그치지 않고 **남기고 싶게** 만드는 것이 목적이다.

---

## 3. 데이터 흐름

```
저장소 주소 입력
   → GitHub API로 참여자별 기여 기록 수집
   → 능력치로 환산
   → 카드 이미지 생성
   → 디스코드 / 웹으로 출력
```

**입력은 저장소 주소 하나로 고정한다.** GitHub 아이디로 조회하는 방식은 API 경로가 달라 코드를 두 벌 짜야 하므로 이번 범위에서 제외한다.

---

## 4. 데이터 형태 (변경 금지)

파일 사이에 오가는 데이터는 아래 형태를 따른다. **키 이름과 타입을 바꾸지 않는다.**

```python
{
    "login":        str,   # GitHub 아이디
    "avatar":       str,   # 프로필 이미지 URL
    "commits":      int,   # 커밋 횟수
    "additions":    int,   # 추가한 줄 수
    "deletions":    int,   # 삭제한 줄 수
    "active_weeks": int,   # 활동한 주 수
}
```

이 형태가 고정되어 있어야 각자 다른 파일을 동시에 작업할 수 있다. 바꿔야 할 일이 생기면 혼자 고치지 말고 팀에 먼저 알린다.

> **참고** — GitHub에는 "수정"이라는 수치가 없다. 한 줄을 고치면 `삭제 1 + 추가 1`로 계산된다.

## 5. 파일 구조

| 파일 | 입력 | 출력 |
|---|---|---|
| `config.py` | — | 능력치 이름·계수, 색상 등 설정값 |
| `fetch.py` | 저장소 주소 | 위 딕셔너리 리스트 (JSON 저장) |
| `stats.py` | 딕셔너리 | 능력치 + 레벨 |
| `card.py` | 능력치 | PNG 이미지 |
| `bot.py` | 디스코드 명령 | 채널에 카드 전송 |
| `web.py` | 저장된 JSON | 순위 페이지 |

```
gitreward/
├── .env               # 토큰 (절대 커밋 금지)
├── .env.example       # 빈 껍데기 (커밋함)
├── config.py
├── fetch.py
├── stats.py
├── card.py
├── bot.py
├── web.py
├── assets/            # 카드 배경, 폰트
├── cache/             # 수집한 JSON
└── docs/
    ├── 기획.md
    └── 함정.md
```

**한 파일은 한 사람만 수정한다.** 이것만 지키면 충돌이 원천적으로 발생하지 않는다.

## 6. 능력치 환산

능력치 이름과 계수는 **2026-08-19 확정됐다.** 바꿔야 할 일이 생기면 혼자 고치지 말고 팀에 먼저 알린다.

| 능력치 | 근거 | 의미 |
|---|---|---|
| ATK | 추가한 줄 수 | 새 기능을 만드는 사람 |
| DEF | 삭제한 줄 수 | 기존 코드를 정리하는 사람 |
| AGI | 커밋 횟수 | 자주 쪼개서 올리는 사람 |
| STA | 활동한 주 수 | 꾸준한 사람 |

커밋 횟수만으로 순위를 매기면 오타를 고친 커밋과 기능을 구현한 커밋이 똑같이 계산된다. 코드 변경량과 활동 기간을 함께 반영해 이를 보완한다.

**이름과 계수는 `config.py`에 모아둔다.** 다른 파일에 직접 적지 않는다. 그래야 코드를 건드리지 않고 조정할 수 있다.

```python
STAT_NAMES    = {"ATK": "ATK", "DEF": "DEF", "AGI": "AGI", "STA": "STA"}
STAT_WEIGHTS  = {"ATK": 1/50, "DEF": 1/50, "AGI": 2, "STA": 5}
LEVEL_DIVISOR = 8
STAT_MAX      = 99
```

**계산은 전부 곱셈으로 통일한다.** 나누는 것과 곱하는 것이 섞여 있으면 사람마다 다르게 구현한다.

계수의 방향이 서로 반대인 이유는 **원래 데이터의 크기가 다르기 때문**이다. 추가·삭제한 줄 수는 수천 단위라 **줄여야** 하고(× 1/50), 커밋 수와 활동 주 수는 작아서 **키워야** 한다(× 2, × 5). 그래야 능력치 넷이 100 안팎의 같은 눈금 위에 놓인다.

```
ATK = additions    × 1/50        DEF = deletions    × 1/50
AGI = commits      × 2           STA = active_weeks × 5

각 능력치는 STAT_MAX(99)를 넘지 않게 자른다
레벨 = (ATK + DEF + AGI + STA) ÷ LEVEL_DIVISOR(8)
```

조정 기준: 여러 저장소를 넣어보며 **레벨이 20~50 사이에 떨어지게** 맞춘다. 전원 Lv.1이거나 전원 Lv.99면 재미가 없다.

넷 다 99까지 채운 사람이 `396 ÷ 8 = Lv.49` 라, 이 값들이면 상한이 목표 구간의 위쪽에 맞는다. 레벨이 전체적으로 높거나 낮게 나오면 계수보다 `LEVEL_DIVISOR` 를 먼저 만지는 편이 빠르다. 전체가 한 번에 오르내리기 때문이다.

## 7. 기술 스택

| 용도 | 사용 |
|---|---|
| 데이터 수집 | Python, requests |
| 이미지 생성 | Pillow |
| 디스코드 봇 | discord.py |
| 웹 | Flask |
| 저장 | JSON 파일 |

**데이터베이스는 쓰지 않는다.** 저장할 데이터가 저장소당 참여자 몇 명 수준이라, 파일 하나를 통째로 읽는 편이 더 빠르고 실수도 적다. 필요해지면 나중에 붙인다.

## 8. 범위

### 이번에 만드는 것

1. 저장소 주소로 참여자별 기여 기록 수집
2. 능력치·레벨 환산
3. 카드 이미지 자동 생성

- 주간 자동 알림
- GitHub 아이디 단위 조회

시간을 가장 많이 잡아먹으면서 결과물에 기여하지 않는 항목들이다.(정말 필요하면 사용할 예정)

- 데이터베이스

## 9. 토큰 관리

| 항목 | 방식 |
|---|---|
| GitHub 토큰 | **각자 발급** (github.com/settings/tokens, 권한 체크 없이) |
| 디스코드 봇 토큰 | **담당자 한 명만** 보유 |
| 서버 ID | 공유 가능 (비밀 아님) |

- 디스코드 봇 토큰은 **동시에 한 사람만** 사용할 수 있다. 두 명이 같은 토큰으로 봇을 켜면 응답이 중복되거나 충돌한다.
- `.env` 파일을 카톡·디스코드로 주고받지 않는다. 채팅 기록에 토큰이 남는다.
- `.gitignore`에 `.env`를 반드시 넣는다. 커밋되면 GitHub이 감지해 토큰을 즉시 무효화한다.

3. **막힌 것은 `docs/함정.md`에 적는다.** 겪은 것만 적는다. 이 기록이 그대로 발표 자료의 트러블슈팅이 된다.
4. **작업 시작 전 `git pull`.**
