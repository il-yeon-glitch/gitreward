## 0. 코드 짜기 전에 정할 것

### 0-1. 계수는 전부 곱셈으로 통일 — **확정 (2026-08-19)**

기획서와 로직도가 서로 다르게 적혀 있었다. 기획서의 변수 이름은 `STAT_DIVISORS`(나누는 수)인데 로직도의 예시는 곱하고 있었다. **곱셈으로 통일하기로 정했고, 기획서를 고쳤다.**

```python
STAT_WEIGHTS  = {"ATK": 1/50, "DEF": 1/50, "AGI": 2, "STA": 5}
LEVEL_DIVISOR = 8
STAT_MAX      = 99
```

방향이 반대인 이유는 원래 데이터의 크기가 달라서다. 줄 수는 수천 단위라 줄이고, 커밋 수와 활동 주 수는 작아서 키운다.

> 사람마다 다르게 구현하기 딱 좋은 지점이었다. 문서 두 개가 어긋나 있으면 **코드를 짜기 전에** 잡는다. 짠 다음에 발견하면 두 사람 코드를 다 고쳐야 한다.

### 0-2. 레벨을 나누는 수 — **확정 (2026-08-19)**

`LEVEL_DIVISOR = 8` 로 기획서에 넣었다. CLAUDE.md 규칙상 숫자를 다른 파일에 직접 적으면 안 되므로 `config.py` 에서 가져다 쓴다.

레벨이 전체적으로 높거나 낮으면 **계수보다 이 숫자를 먼저 조절**하는 게 빠르다. 전체가 한 번에 오르내리기 때문이다.

### 0-3. 아직 git 저장소가 아니다 — **남아 있음**

기획서 10번에 "작업 시작 전 `git pull`"이 있는데, 이 폴더는 아직 git 저장소가 아니다.
`.gitignore` 는 만들어 뒀다. 남은 것은 `git init` → 원격 저장소 연결이다.

**`.gitignore` 가 있는지 확인하기 전에는 커밋하지 않는다.** 토큰이 한 번 올라가면 GitHub이 감지해 즉시 무효화한다. 첫 커밋 직전에 `git status` 를 보고 `.env` 가 목록에 없는지 눈으로 확인한다.

## 1. 공통 — 윈도우 / 한글 환경

### 1-1. JSON 저장할 때 인코딩 ★거의 확실히 겪는다

한글 윈도우의 파이썬은 파일을 열 때 기본 인코딩이 `cp949`다. UTF-8이 아니다.

```python
# 이렇게 하면 한글이 깨지거나 UnicodeEncodeError 가 난다
open("cache/x.json", "w")

# 반드시 인코딩을 지정한다
open("cache/x.json", "w", encoding="utf-8")
```

저장할 때 `json.dump(data, f, ensure_ascii=False)` 를 같이 쓴다. 안 쓰면 한글이 `\uc548\ub155` 같은 코드로 저장돼 파일을 열어봐도 읽을 수 없다. 읽을 때도 `encoding="utf-8"` 을 똑같이 붙인다.

### 1-2. 폴더가 없으면 파일을 못 만든다

`cache/`, `assets/` 폴더가 없는 상태에서 그 안에 파일을 쓰면 `FileNotFoundError` 가 난다.
파일을 쓰기 전에 폴더를 만든다.

```python
os.makedirs("cache", exist_ok=True)   # 이미 있어도 에러 안 남
```

### 1-3. 저장소 이름을 그대로 파일명으로 쓰면 안 된다

`facebook/react` 의 `/` 는 경로 구분자다. `cache/facebook/react.json` 으로 해석돼 폴더가 없다며 실패한다.

```python
"facebook/react".replace("/", "_")   →  "facebook_react.json"
```

### 1-4. 프로젝트 경로는 `C:\dev\gitreward` 에 둔다

```
C:\dev\gitreward
```

바탕 화면(`OneDrive\바탕 화면\...`)에 두지 않는다. 세 가지가 한꺼번에 걸린다.

- **공백** — `바탕 화면` 에 띄어쓰기가 있어서, 터미널에서 따옴표로 감싸지 않으면 `바탕` 까지만 경로로 인식한다
- **한글** — 도구에 따라 한글 경로를 못 읽는 경우가 있다
- **OneDrive 동기화** — 동기화 중에는 파일이 잠겨 저장이 실패할 때가 있다. 이유 없이 저장이 안 되면 OneDrive 아이콘을 먼저 본다

**폴더를 옮긴 뒤에는 터미널을 새로 열고 `cd C:\dev\gitreward` 부터 한다.** 옛날 경로에 열어둔 터미널에서 계속 실행하면, 고친 파일과 실행되는 파일이 달라 원인을 못 찾는다.

### 1-5. `.env` 는 읽기 전에 불러와야 한다

`os.getenv()` 는 `.env` 파일을 자동으로 읽지 않는다. `load_dotenv()` 를 **먼저** 호출해야 한다.

```python
from dotenv import load_dotenv
load_dotenv()                      # 이게 먼저
token = os.getenv("GITHUB_TOKEN")  # 그 다음
```

값이 `None` 으로 나오면 대개 ① `load_dotenv()` 를 안 불렀거나 ② `.env` 가 실행 위치와 다른 폴더에 있거나 ③ 이름 철자가 다른 경우다.

## 2. fetch.py — GitHub API

### 2-1. 응답 형태와 우리 데이터 형태가 다르다 ★가장 헷갈리는 지점

`/repos/{owner}/{repo}/stats/contributors` 응답은 이렇게 생겼다.

```json
[
  {
    "author": { "login": "hong", "avatar_url": "https://..." },
    "total": 42,
    "weeks": [ { "w": 1234567890, "a": 120, "d": 30, "c": 5 }, ... ]
  }
]
```

`a`=추가, `d`=삭제, `c`=커밋, `w`=주 시작 시각이다. 우리 형태로 옮기면 이렇게 대응된다.

| GitHub 응답 | → | 우리 키 |
|---|---|---|
| `author.login` | → | `login` |
| `author.avatar_url` | → | `avatar` ← **이름이 다르다** |
| `total` | → | `commits` |
| `weeks` 의 `a` 전부 더하기 | → | `additions` |
| `weeks` 의 `d` 전부 더하기 | → | `deletions` |
| `weeks` 중 `c > 0` 인 개수 | → | `active_weeks` |

`avatar_url` 을 그대로 `avatar_url` 키로 저장하면 `card.py` 가 못 읽는다. 데이터 형태는 기획서가 정한 `avatar` 다.

`additions` 는 `total` 같은 필드가 따로 없다. **주 단위 값을 직접 합해야 한다.**

### 2-2. `author` 가 `null` 일 수 있다 ★실제 저장소에서 자주 나온다

커밋의 이메일이 GitHub 계정과 연결돼 있지 않으면 `author` 가 `null` 로 온다.
이때 `c["author"]["login"]` 은 `TypeError: 'NoneType' object is not subscriptable` 로 터진다.

```python
if c["author"] is None:
    continue      # 계정 연결 안 된 기여자는 건너뛴다
```

### 2-3. 첫 호출은 202 를 준다 (이미 알려진 함정)

GitHub이 통계를 계산하는 동안 **202 와 빈 본문**을 돌려준다. 재시도해야 한다.
2초쯤 쉬고 다시 요청하기를 5번 정도 반복한다. `status_code == 200` 이고 내용이 비어 있지 않을 때만 진행한다.

큰 저장소는 첫 계산에 시간이 더 걸린다. 시연 직전에 처음 호출하지 말고, **미리 한 번 돌려 `cache/` 에 저장해 둔다.**

### 2-4. 토큰 없이 부르면 금방 막힌다

| 상태 | 시간당 요청 |
|---|---|
| 토큰 없음 | 60회 |
| 토큰 있음 | 5,000회 |

테스트하다 보면 60회는 순식간이다. 막히면 403 또는 429가 오고 응답 헤더의 `X-RateLimit-Remaining` 이 0이다. 처음부터 토큰을 붙여서 부른다.

```python
headers = {"Authorization": f"Bearer {token}"}
```

### 2-5. 비공개 저장소는 403이 아니라 404 가 온다

권한이 없으면 GitHub은 "없음"이라고 답한다. 저장소가 있는지 헷갈리게 만드는 지점이다.
주소를 잘못 친 것 같은데 맞다면, **비공개 저장소인데 토큰 권한이 없는 경우**를 의심한다.

### 2-6. 입력 주소 형태가 제각각이다

```
https://github.com/facebook/react
https://github.com/facebook/react.git
https://github.com/facebook/react/
facebook/react
```

전부 `facebook/react` 로 정리한 뒤 API를 부른다. 시연 때 팀원이 어떤 형태로 넣을지 모른다.

### 2-7. 기여자는 최대 100명까지만 온다

`/stats/contributors` 는 상위 100명만 준다. 팀 저장소는 문제없지만, `facebook/react` 같은 대형 저장소로 테스트하면 전원이 아니라는 걸 알고 있어야 한다.

### 2-8. 새 저장소는 빈 응답이 온다

커밋이 없는 저장소는 `204` 또는 빈 배열을 준다. 202 재시도 반복문이 무한정 도는 원인이 될 수 있다.
**재시도 횟수 상한을 반드시 둔다.**

## 3. stats.py / config.py — 능력치 환산

### 3-1. 나눗셈 결과가 소수로 나온다

파이썬 3에서 `1203 / 50` 은 `24.06` 이다. 카드에 `ATK 24.06` 이 찍힌다.
`//` (몫만 남기는 나눗셈) 또는 `int()` 로 정수를 만든다.

### 3-2. 레벨 0 이 나올 수 있다

기여가 적은 사람은 합이 8 미만이라 `Lv.0` 이 된다. 고장난 것처럼 보인다.
최소 1로 올린다. `max(1, level)`

### 3-3. 능력치끼리 크기 차이가 크다

예시에서 AGI 84, DEF 9다. 막대 길이를 **각 능력치의 실제 값 기준**으로 그리면 DEF는 거의 보이지 않는다.
막대의 기준 최대값(예: 100)을 `config.py` 에 두고, 그걸 넘으면 꽉 찬 막대로 자른다. 이건 `card.py` 와 함께 정할 문제다.

### 3-4. 계수를 코드에 직접 적지 않는다

`additions // 50` 처럼 쓰면 나중에 밸런스를 조정할 때 여러 파일을 뒤져야 한다.
`config.py` 의 값을 가져다 쓴다. 이건 CLAUDE.md 규칙이기도 하다.

## 4. card.py — Pillow

### 4-1. 한글 폰트 (이미 알려진 함정)

폰트를 지정하지 않으면 한글이 네모(`□□□`)로 나온다.
`ImageFont.load_default()` 도 한글이 안 되고 글자도 아주 작다.

```python
ImageFont.truetype("assets/폰트파일.ttf", 크기)
```

**폰트 파일을 `assets/` 에 같이 넣는다.** `C:/Windows/Fonts/malgun.ttf` 를 직접 가리키면 내 컴퓨터에서만 되고 맥 쓰는 팀원 컴퓨터에서는 실패한다.

### 4-2. 프로필 사진은 URL이라 다운로드해야 한다

`avatar` 에 들어 있는 건 주소일 뿐 이미지가 아니다.

```python
res = requests.get(avatar_url)
img = Image.open(BytesIO(res.content))   # bytes 를 BytesIO 로 감싸야 한다
```

`Image.open(res.content)` 는 안 된다. 파일 같은 물건을 넘겨야 한다.

### 4-3. 투명한 PNG 를 붙이면 검은 사각형이 된다

```python
bg.paste(avatar, (x, y))            # 투명 부분이 검게 나온다
bg.paste(avatar, (x, y), avatar)    # 세 번째 인자가 마스크. 이게 있어야 한다
```

프로필을 동그랗게 자르려면 원 모양 마스크를 따로 만들어 세 번째 인자로 넘긴다.

### 4-4. 긴 아이디가 카드 밖으로 나간다

GitHub 아이디는 최대 39자다. 카드 폭을 넘어가면 그냥 잘려 나온다.
글자 길이를 재서(`draw.textlength`) 넘치면 글자 크기를 줄이거나 `...` 로 자른다.

### 4-5. 색상·크기를 코드에 적지 않는다

`(255, 100, 100)`, `800`, `450` 같은 값은 전부 `config.py` 로 뺀다.
디자인 담당이 색을 바꿀 때 `card.py` 를 안 열어도 되게 만드는 게 목적이다.

## 5. bot.py — 디스코드

### 5-1. `defer()` 다음에는 `followup` 을 쓴다 ★알려진 함정과 짝이다

3초 넘으면 실패하니 `defer()` 를 먼저 부르는 건 이미 알고 있다.
그런데 **`defer()` 를 부른 뒤에 다시 `interaction.response.send_message()` 를 부르면 에러가 난다.** 응답은 한 번뿐이기 때문이다.

```python
await interaction.response.defer()          # 1) 먼저 시간 벌기
...카드 만드는 오래 걸리는 작업...
await interaction.followup.send(file=...)   # 2) 결과는 followup 으로
```

`InteractionResponded` 에러가 나면 거의 이 경우다.

### 5-2. 봇 초대 링크에 `applications.commands` 가 없으면 명령이 안 보인다

`bot` 권한만 주고 초대하면 봇은 서버에 들어오지만 슬래시 명령이 목록에 뜨지 않는다.
개발자 포털의 초대 URL 생성기에서 **`bot` 과 `applications.commands` 를 둘 다** 체크한다.

명령이 안 보일 때 확인 순서: ① 초대 권한 ② 길드 sync 했는지 ③ 디스코드 앱 재시작(`Ctrl+R`)

### 5-3. `discord.File` 은 한 번만 보낼 수 있다

같은 `File` 객체를 두 번 보내면 두 번째는 빈 파일이 간다. 이미 다 읽었기 때문이다.
`BytesIO` 도 마찬가지라 `seek(0)` 이 필요한 것이다(알려진 함정). 보낼 때마다 새로 만든다.

### 5-4. `requests` 는 봇 전체를 멈춘다

디스코드 봇은 비동기(async)로 돈다. 여러 일을 번갈아 처리하는 방식인데, `requests.get()` 은 응답이 올 때까지 그 자리에 **완전히 멈춰 선다.** 그동안 봇은 다른 명령도, 하트비트도 처리하지 못한다.

해커톤 규모에서는 그냥 써도 시연은 된다. 다만 카드 만드는 데 10초 걸리면 그 10초 동안 봇이 먹통이라는 걸 알고 있어야 한다. **그래서 `cache/` 에 미리 저장해 두는 게 중요하다.** 시연 때는 API를 다시 부르지 않는 편이 안전하다.

### 5-5. 토큰은 동시에 한 명만

기획서에 있는 내용이지만 실제로 겪으면 증상이 헷갈린다. 두 명이 같은 토큰으로 봇을 켜면 **응답이 두 번 오거나, 한쪽이 조용히 끊긴다.** 봇이 이상하게 굴면 팀에 "지금 봇 켠 사람 있냐"고 먼저 물어본다.

### 5-6. 종료할 때 나오는 빨간 글씨

윈도우에서 봇을 끄면 `RuntimeError: Event loop is closed` 가 뜰 때가 있다. 동작에는 영향이 없다. 이걸 고치려고 시간 쓰지 않는다.

## 6. web.py — Flask

### 6-1. `cache/` 안의 이미지는 브라우저가 못 읽는다

Flask는 `static/` 폴더에 있는 파일만 주소로 열어준다. `cache/` 나 프로젝트 폴더에 만든 PNG는 아무리 경로를 적어도 404다.

카드 이미지를 `static/` 에 저장하거나, `send_file()` 로 직접 내보낸다.

### 6-2. 카드를 새로 만들었는데 웹에서는 그대로다

브라우저가 같은 이름의 이미지를 캐시해 둔 것이다. 새로고침해도 옛날 그림이 나온다.
주소 뒤에 바뀌는 값을 붙이면 다른 파일로 취급한다.

```
/static/hong.png?v=1234567
```

급할 땐 `Ctrl + F5` (캐시 무시 새로고침).

### 6-3. 5000 포트가 이미 쓰이는 중일 수 있다

맥에서는 시스템 기능이 5000번을 쓴다. 안 되면 `app.run(port=5001)` 로 바꾼다.

### 6-4. `debug=True` 면 코드가 두 번 실행된다

자동 새로고침 기능 때문에 파일 맨 바깥에 적은 코드가 두 번 돈다. API를 두 번 부르거나 로그가 두 줄씩 찍히면 이 때문이다.

## 7. 시연 직전 점검표

발표 당일 아침에 이것만 확인한다.

- [ ] `cache/` 에 우리 팀 저장소 JSON이 **저장돼 있다** (와이파이 끊겨도 데모가 돌아간다)
- [ ] `cache/demo_*.json` 이 **커밋되어 있다** (`git status` 말고 `git ls-files cache/` 로 확인한다. 누가 클론해도 데모가 돌아가야 한다)
- [ ] 봇을 켤 사람 **한 명**을 정했다
- [ ] 봇이 서버에 들어와 있고 슬래시 명령이 목록에 보인다
- [ ] 카드에 한글이 네모로 안 깨진다
- [ ] `.env` 가 커밋되지 않았다 (`git status` 에 안 보여야 한다)
- [ ] 시연할 명령을 실제로 **한 번 쳐 봤다**
