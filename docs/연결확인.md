# 연결 확인

> 코드를 쓰기 전에 **GitHub API 와 디스코드 봇이 실제로 붙는지** 먼저 확인한다.
> `check_github.py` / `check_discord.py` 두 개. 기능은 없고 연결만 본다.
> 여기서 막히면 `fetch.py` 든 `bot.py` 든 만들어도 안 돌아간다.

각자 자기 컴퓨터에서 한 번씩 돌려본다. 아래 **[확인 체크리스트](#4-확인-체크리스트)** 4개가 전부 통과하면 준비 끝이다.

---

## 0. 준비 (처음 한 번만)

### 가상환경 만들기

```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

프롬프트 앞에 `(.venv)` 가 붙으면 켜진 것이다. **터미널을 새로 열 때마다 `activate` 를 다시 해야 한다.**

제대로 켜졌는지 확인:

```
python -c "import sys; print(sys.executable)"
```

`C:\dev\gitreward\.venv\Scripts\python.exe` 가 나와야 한다. 다른 경로가 나오면 전역 파이썬이 잡힌 것이라 라이브러리가 없다고 나온다.

`.venv` 폴더는 55MB 쯤 되고 `.gitignore` 에 들어 있다. **커밋되지 않으니 각자 만들어야 한다.**

### `.env` 채우기

```
copy .env.example .env
```

복사한 뒤 값 3개를 채운다.

| 값 | 어디서 받나 | 누가 |
|---|---|---|
| `GITHUB_TOKEN` | [github.com/settings/tokens](https://github.com/settings/tokens) → 권한(scope) 체크 안 해도 된다 | **각자** 발급 |
| `DISCORD_TOKEN` | 디스코드 개발자 포털 → 내 앱 → Bot 탭 | **담당자 한 명만** |
| `DISCORD_GUILD_ID` | 디스코드 설정에서 개발자 모드 ON → 서버 이름 우클릭 → "서버 ID 복사" | 팀 공유 (비밀 아님) |

- `.env` 는 `.gitignore` 에 있어서 커밋되지 않는다.
- **`.env` 를 카톡·디스코드로 주고받지 않는다.** 채팅 기록에 토큰이 남는다.
- 디스코드 봇 토큰은 **동시에 한 명만** 쓸 수 있다. 두 명이 같은 토큰으로 봇을 켜면 응답이 두 번 오거나 한쪽이 조용히 끊긴다.

## 1. GitHub 확인 — `check_github.py`

토큰이 살아 있는지, 참여자 통계를 받아올 수 있는지 두 가지를 본다.
받은 응답에서 값을 꺼내지 않고 **구조를 그대로 보여준다.**

### 실행

```
python check_github.py                        # 기본값 octocat/Hello-World
python check_github.py Krishita17/KeyWraith   # 202 를 직접 보고 싶을 때
```

### 정상 출력

```
확인할 저장소: octocat/Hello-World

[1단계] 토큰 확인
  GET https://api.github.com/user
  응답 코드: 200
  토큰 주인: il-yeon-glitch          ← 각자 자기 아이디가 나온다
  남은 요청 횟수: 4999 / 5000  (5000 이면 토큰이 붙은 것, 60 이면 안 붙은 것)

[2단계] 참여자 통계 요청
  GET https://api.github.com/repos/octocat/Hello-World/stats/contributors
  1번째 시도 -> 200 (본문 58913바이트)

[3단계] 받은 응답
  ...JSON 원본...
```

**볼 것은 딱 하나 — `남은 요청 횟수` 가 5000 인가.** 5000이면 토큰이 제대로 붙은 것이고, 60이면 토큰 없이 요청한 것이다. 60인 상태로도 응답은 오기 때문에 이걸 안 보면 토큰이 안 붙은 줄 모르고 넘어간다.

### 202 확인하기

`/stats/contributors` 는 첫 호출에서 **202 와 빈 응답(2바이트)** 을 준다. GitHub 이 통계를 계산하는 중이라는 뜻이다. 스크립트가 2초 쉬고 재시도한다.

```
  1번째 시도 -> 202 (본문 2바이트)
     202: 아직 계산 중이고 본문이 비어 있다. 2초 기다렸다 다시 물어본다.
  2번째 시도 -> 200 (본문 1025바이트)
```

**유명한 저장소는 202 가 안 뜬다.** GitHub 이 이미 계산해서 캐시해 뒀기 때문이다. `octocat/Hello-World`, `psf/requests`, `pallets/flask` 는 전부 첫 호출에 바로 200 이 온다.
그래서 유명한 저장소로만 테스트하면 **재시도 코드 없이도 잘 되는 줄 알고 넘어갔다가, 시연 때 우리 팀 저장소에서 터진다.** 202 는 아무도 최근에 조회하지 않은 저장소에서만 나온다.

### 응답 구조

참여자 한 명이 딕셔너리 하나다.

```json
[
  {
    "total": 2,
    "weeks": [
      { "w": 1786838400, "a": 15953, "d": 252, "c": 2 }
    ],
    "author": { "login": "...", "avatar_url": "...", ... }
  }
]
```

| 키 | 뜻 |
|---|---|
| `total` | 그 사람의 전체 커밋 수 |
| `weeks` | 주 단위 기록 |
| `weeks[].w` | 그 주의 시작 시각 (유닉스 초) |
| `weeks[].a` / `d` / `c` | 추가한 줄 / 삭제한 줄 / 커밋 수 |
| `author.login` / `author.avatar_url` | 아이디 / 프로필 이미지 URL |

기획서의 **고정 데이터 형태**와 이렇게 이어진다. 이 변환이 `fetch.py` 가 할 일이다.

```
login        ← author.login
avatar       ← author.avatar_url
commits      ← total
additions    ← weeks 의 a 를 전부 더한 값
deletions    ← weeks 의 d 를 전부 더한 값
active_weeks ← c 가 0 보다 큰 주의 개수
```

> 큰 저장소는 응답이 크다. `psf/requests` 2.9MB, `python-pillow/Pillow` 13.7MB.
> 구조를 눈으로 볼 목적이면 작은 저장소로 본다.

### 안 될 때

| 증상 | 원인 | 해결 |
|---|---|---|
| `ModuleNotFoundError: No module named 'dotenv'` | 패키지 이름은 `python-dotenv` 인데 import 이름은 `dotenv` 다 | `pip install -r requirements.txt` |
| `GITHUB_TOKEN 이 없다` | `.env` 를 안 만들었거나 값이 비었다 | `.env` 확인 |
| 응답 코드 `401` | 토큰이 틀렸거나 만료됐다 | 토큰 재발급 |
| 남은 요청 횟수가 `60` | 토큰이 안 붙었다 | `.env` 위치 확인 (아래) |
| 다른 폴더에서 실행하니 `401` | `load_dotenv()` 는 실행 위치가 아니라 **스크립트 파일이 있는 폴더** 기준으로 `.env` 를 찾는다 | 프로젝트 폴더 안에서 실행 |
| `5번 시도했는데 계속 202` | 큰 저장소라 계산이 오래 걸린다 | 잠시 뒤 다시 실행 |

## 2. 디스코드 확인 — `check_discord.py`

봇이 서버에 붙는지, 슬래시 명령이 그 서버에 등록되는지 두 가지를 본다.

### 실행

```
python check_discord.py
```

**이건 끝나지 않고 계속 떠 있다.** `check_github.py` 와 다른 점이다.
봇이 켜져 있어야 `/ping` 에 답할 수 있으니, 확인이 끝날 때까지 터미널을 닫지 않는다.

### 정상 출력

```
봇 이름: Git Reward#2588  (ID: 1539300210432409611)
접속한 서버: 1개
  - Git Reward  (ID: 1539304629261701140)

[슬래시 명령 등록] Git Reward
  등록된 명령: 1개
  - /ping

디스코드 앱에서 이 서버 채팅창에 / 를 눌러 목록에 /ping 이 보이는지 확인한다.
```

`등록된 명령: 1개` / `- /ping` 이 나오면 sync 는 성공한 것이다.

### 디스코드 앱에서 확인

1. 디스코드 앱에서 해당 서버로 간다
2. 아무 채팅창에 `/` 를 입력한다
3. 목록에 **`/ping`** 이 보인다
4. 실행하면 **`pong`** 이 온다

확인이 끝나면 터미널에서 `Ctrl+C` 로 끈다.

### 목록에 보이는 것과 응답하는 것은 다르다

한 번 sync 하면 `/ping` 은 **봇이 꺼져 있어도 목록에 계속 남아 있다.** 등록 정보가 디스코드 서버 쪽에 저장되기 때문이다.
하지만 봇이 꺼져 있으면 실행했을 때 `애플리케이션이 응답하지 않았습니다` 가 뜬다. **이건 명령이 잘못된 게 아니라 봇이 안 켜져 있는 것이다.**

### 안 될 때

| 증상 | 원인 | 해결 |
|---|---|---|
| `DISCORD_GUILD_ID(...) 서버에 봇이 안 들어가 있다` | ID 가 틀렸거나 그 서버로 초대를 안 했다 | 출력된 서버 목록과 ID 를 비교. 목록이 0개면 초대부터 |
| 목록에 `/ping` 이 안 보인다 | ① 초대 링크에 `applications.commands` 가 없었다 ② sync 가 안 됐다 ③ 앱 화면이 오래됐다 | ① 개발자 포털 초대 URL 생성기에서 `bot` 과 `applications.commands` **둘 다** 체크해 다시 초대 ② 위 출력에 `등록된 명령: 1개` 가 나왔는지 확인 ③ `Ctrl+R` 로 앱 새로고침 |
| `애플리케이션이 응답하지 않았습니다` | 봇이 꺼져 있다 | 터미널에서 `check_discord.py` 를 다시 켠다 |
| 응답이 두 번 오거나 봇이 조용히 끊긴다 | 두 명이 같은 토큰으로 봇을 켰다 | 팀에 "지금 봇 켠 사람 있냐" 고 물어본다 |
| 끌 때 `RuntimeError: Event loop is closed` | 윈도우에서 나오는 메시지 | **무해하다. 고치려고 시간 쓰지 않는다.** |

### 코드에서 알아둘 것

```python
GUILD = discord.Object(id=int(GUILD_ID.strip()))

@tree.command(name="ping", description="...", guild=GUILD)
async def ping(interaction):
    await interaction.response.send_message("pong")
```

- `discord.Object` 는 서버 정보를 받아오지 않고 **ID 만 감싼 가벼운 참조**다. 어느 서버에 등록할지 지정하는 용도라 이것으로 충분하다.
- **`guild=GUILD` 를 빼면 전역 등록이 된다.** 전역 등록은 디스코드 반영이 한 시간까지 걸려서 해커톤에선 못 쓴다. 반드시 길드 한정으로 등록한다.
- `/ping` 은 바로 답할 수 있어서 `defer()` 없이 곧장 응답한다. **카드 생성처럼 3초를 넘기는 명령은 `await interaction.response.defer()` 를 먼저 부르고, 결과는 `interaction.followup.send()` 로 보내야 한다.** (`bot.py` 에서 필요해진다)
- `commands.Bot` 대신 `discord.Client` + `app_commands.CommandTree` 를 쓴다. `commands.Bot` 은 `!ping` 같은 접두사 명령용이라 `Privileged message content intent is missing, commands may not work as expected` 경고를 띄우는데, 슬래시 명령과는 무관한 경고지만 헷갈린다.

## 3. 라이브러리 확인

`.venv` 안에 5개가 들어 있어야 한다.

```
.venv\Scripts\python.exe -m pip list
```

| 라이브러리 | 용도 |
|---|---|
| `requests` | GitHub API 호출 |
| `Pillow` | 카드 이미지 생성 |
| `python-dotenv` | `.env` 읽기 |
| `discord.py` | 디스코드 봇 |
| `Flask` | 웹 순위 페이지 |

목록에 25개가 나와도 정상이다. 나머지 20개는 위 5개가 **알아서 끌고 온 것들**이다.
`requests` 가 `certifi`·`urllib3` 를, `Flask` 가 `Jinja2`·`Werkzeug`·`click` 을, `discord.py` 가 `aiohttp` 계열을 데려온다.

### 라이브러리를 새로 추가했다면

`requirements.txt` 를 다시 만들어 커밋한다. **`>` 를 쓰지 않는다.**

```
.venv\Scripts\python.exe -m pip freeze | Out-File -Encoding utf8 requirements.txt
```

PowerShell 의 `>` 는 기본 인코딩이 **UTF-16** 이라 `pip freeze > requirements.txt` 로 만들면 git 이 이 파일을 바이너리로 취급한다. pip 은 읽지만 `git diff` 가 `Binary files differ` 만 보여줘서 누가 뭘 추가했는지 안 보인다.

## 4. 확인 체크리스트

- [ ] `python -c "import sys; print(sys.executable)"` 가 `.venv` 경로를 가리킨다
- [ ] `check_github.py` — `남은 요청 횟수` 가 **5000** 이다
- [ ] `check_discord.py` — `등록된 명령: 1개` / `- /ping` 이 나온다
- [ ] 디스코드 앱에서 `/ping` 을 실행하면 **`pong`** 이 온다

4개가 전부 되면 `config.py` → `fetch.py` 로 넘어간다.

## 이 두 파일은 왜 따로 있나

`check_github.py` 와 `check_discord.py` 는 **기획서의 6개 파일에 들어가지 않는다.** 연결만 확인하는 임시 스크립트라서, 기능이 완성되면 안 써도 된다.
그래도 지우지 않는다. 나중에 봇이 이상하게 굴 때 **"내 문제냐 연결 문제냐"** 를 30초 만에 가르는 데 쓴다.
